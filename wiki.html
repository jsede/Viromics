Viromics Technical Wiki

Viromics is an end-to-end, scientifically validated computational platform for amplicon-based viral whole-genome sequencing (WGS) and genomic epidemiology. It unites a high-throughput Nextflow DSL2 workflow with an interactive, zero-backend React 18 client-side analytics dashboard.

🧬 Nextflow DSL2 🔬 Illumina & Oxford Nanopore ⚡ Zero-Database Dashboard 📊 NJ & UPGMA Phylogenetics 📑 Programmed Frameshift Engine

1. Architecture & Design Principles

Viral amplicon sequencing presents unique bioinformatics challenges: overlapping PCR primer schemes, severe depth gradients across amplicons, low-frequency subclonal variants, atypical biological mechanisms like programmed -1 ribosomal frameshifts (e.g. SARS-CoV-2 ORF1ab), and potential multi-strain viral co-infections.

🚀 Modular Pipeline (Nextflow DSL2)

Decoupled stages with staged reference indexing, rigorous quality filtering, amplicon primer clipping, and haploid variant calling with IUPAC support.

🖥️ Client-Side Web Dashboard

100% browser-based React 18 application requiring no database, API servers, or external cloud services. Consumes a single structured JSON report.

🛡️ Fail-Closed Biology

Never guesses amino-acid changes for unsupported translation exceptions. Programmed frameshifts require explicit curated interval models.

🌐 Multi-Reference Co-Detection

Simultaneously aligns and profiles multiplexed samples against multi-contig references (e.g. RSV-A and RSV-B) with automatic co-infection classification.

Pipeline Process Flow (DSL2 DAG)

Raw FASTQ (Illumina/ONT) ➔ FASTQ_QC (fastp / fastplong) ➔ INDEX_REFERENCE & ALIGN_READS (BWA/Minimap2) ➔ PRIMER_TRIM (ampliconclip)
↳ VARIANT_CALL (bcftools -B -X + norm) ➔ CONSENSUS_GEN (depth -aa -J -Q -q + bcftools) ➔ AGGREGATE_METRICS (parse_metrics.py + schema) ➔ viromics_run_report.json

1. Pipeline Environment Setup (Conda / Micromamba)

The pipeline automatically activates required bioconda packages when executed with -profile conda. Alternatively, create an isolated environment with all command-line tools:

BASH 
# Create conda environment with all underlying bioinformatics utilities
conda create -n viromics -c conda-forge -c bioconda nextflow fastp fastplong bwa minimap2 "samtools>=1.20" "bcftools>=1.20" python

# Activate environment
conda activate viromics

3. Quickstart Guide

Viromics includes a verified Illumina SARS-CoV-2 amplicon sequencing dataset in example_data/illumina_SARS2/. Execute the complete workflow with one command:

BASH — Run SARS-CoV-2 Illumina Example 
nextflow run pipeline/main.nf   --platform illumina   --sample_sheet example_data/illumina_SARS2/samplesheet.csv   --reference example_data/illumina_SARS2/refs/ref.SARS-CoV-2.fasta   --gff example_data/illumina_SARS2/refs/ref.SARS-CoV-2.gff   --primer_bed example_data/illumina_SARS2/refs/primer_scheme.SARS-CoV-2-Eden.bed   --metadata example_data/illumina_SARS2/metadata.csv   --outdir results/illumina_sars2   -profile conda

Once finished, launch the dashboard or preview the output report:

BASH — Launch Web Dashboard 
cd dashboard
npm run dev
# Open http://localhost:5173 and drag results/illumina_sars2/viromics_run_report.json into the UI

7. Multi-Strain & Viral Co-Infection Detection

Viromics natively supports multi-FASTA reference files. This is essential for respiratory multiplex panels (e.g. distinguishing RSV-A and RSV-B, or Influenza A subtypes H1N1 and H3N2) where multiple viruses or strains may co-exist within a single clinical specimen.

Co-Detection Classification Logic

When a reference multi-FASTA has $N$ target strains, the aggregator computes coverage breadth ($\ge \text{minCoverageThreshold}$) independently for every strain. If a sample exhibits $\ge 50\%$ coverage breadth across multiple reference contigs, Viromics flags the sample with a Co-detection Badge (e.g. Co-detection: RSV-A + RSV-B) and generates dedicated mutation tables for each strain in the genomics report.

8. Underlying Tools & Pipeline Stages

Each pipeline stage utilizes gold-standard bioinformatics utilities configured with specific parameters for amplicon viral sequencing:

1. FASTQ_QC

Tools: fastp (Illumina) / fastplong (ONT)
Illumina runs fastp directly on raw paired reads with --detect_adapter_for_pe --cut_tail --trim_poly_g. ONT runs fastplong with mean-read quality filtering (--mean_qual), length bounds, and -A by default to protect conserved viral amplicon ends.

2. INDEX & ALIGN

Tools: BWA-MEM / Minimap2 + Samtools
References are pre-indexed once via INDEX_REFERENCE. Reads are aligned (BWA-MEM for Illumina; Minimap2 -ax map-ont --secondary=no for ONT) and filtered with samtools view -F 0x904 -q to drop unmapped, secondary, supplementary, and low-MAPQ reads.

3. PRIMER_TRIM

Tools: Samtools ampliconclip (+ fixmate)
Strand-aware primer soft-clipping at both ends (--both-ends --strand --soft-clip --tolerance --filter-len --no-excluded), followed by samtools fixmate for paired-end Illumina reads.

4. VARIANT_CALL

Tools: BCFtools mpileup, call, norm & filter
Deterministic strand-balanced BAM downsampling above max_mpileup_depth, followed by bcftools mpileup (-B no-BAQ, -X illumina/ont-sup, FORMAT/AD,FORMAT/DP), diploid calling, bcftools norm -m -any, and decoupled reported vs. consensus VCFs.

5. CONSENSUS_GEN

Tools: Samtools depth + BCFtools consensus
Uses samtools depth -aa -J -Q -q -G 0xF04 synced exactly with variant calling. Masks sites below min_consensus_depth with N, applies only major alleles (AF ≥ min_consensus_freq) in haploid mode, or biallelic SNP IUPAC codes via -H I.

6. AGGREGATE_METRICS

Tools: parse_metrics.py + Schema v2.0.0
Annotates variants with GFF3 & staged curated frameshift models, computes callable-target QC tiers, indel-safe low-coverage intervals, pairwise SNP distances, tool provenance (versions.yml), and validates against schema/viromics_run_report.schema.json.

9. Default Settings & Scientific Assumptions

Sample Quality Classification Rules (Callable Target)

The pipeline evaluates sample alignments against reference targets into three configurable quality tiers (--qc_pass_* / --qc_warn_*). When --primer_bed is supplied, metrics are evaluated across the union of primer-trimmed insert intervals [left_end, right_start] so clipped terminal primer bases never penalize short single-amplicon assays; whole-contig metrics are always reported alongside:

Tier Callable Mean Depth Callable Breadth (≥ minCov) Internal N Rate Clinical Interpretation
PASS ≥ 100x (--qc_pass_depth) ≥ 95.0% (--qc_pass_breadth) ≤ 5.0% (--qc_pass_max_n) High-confidence genome assembly suitable for molecular epidemiology and clade assignment.
WARN ≥ 25x (--qc_warn_depth) ≥ 80.0% (--qc_warn_breadth) ≤ 10.0% (--qc_warn_max_n) Acceptable for variant identification; some low-coverage genomic regions masked with Ns.
FAIL < 25x < 80.0% > 10.0% Insufficient coverage or excessive dropout. Excluded from phylogenetic tree reconstruction.

Haploid Genome Biology & Subclonal Decoupling

Viral genomes (e.g. coronaviruses, flaviviruses, paramyxoviruses) exist as haploid populations. To capture true intra-host subclonal variants (e.g. Illumina AF ≥ 0.20) without distorting consensus sequences, Viromics runs diploid likelihood calling followed by bcftools norm -m -any and strictly decouples the reported VCF from the consensus VCF: haploid consensus applies only major alleles (AF ≥ --min_consensus_freq, default 0.50), while --use_iupac restricts IUPAC ambiguity codes to mixed biallelic SNPs within [--min_iupac_freq, --max_iupac_freq) and keeps indels major-allele only.

Deletion Protection in Depth Masking

Standard depth calculations can mistake true biological deletions (e.g. spike 69-70del) for sequencing failures. Viromics executes samtools depth -aa -J -Q -q -G 0xF04 synced to the exact MAPQ and BaseQ filters of VARIANT_CALL, where -J incorporates reads spanning deletion junctions so authentic deletions are never masked as N while low-MAPQ cross-mappings are excluded.

10. Curated CDS Models & Ribosomal Slippage

In viruses such as SARS-CoV-2, key proteins like ORF1ab polyprotein are translated via a programmed -1 ribosomal frameshift (ribosomal slippage) at a slippery heptanucleotide motif (UUUAAAC) followed by an RNA pseudoknot. Traditional naive GFF parsers fail because the two coding exons are in different reading frames.

Fail-Closed Safety Guarantee

Viromics follows a strict fail-closed policy. GFF3 phase offsets are subtracted from the 5' coding end with strict partial-codon bounds checks, and curated models validate both reference aliases/patterns and slippery-site sequence motifs (motif_check). If a GFF feature indicates a translation exception without a verified curated model, it returns:
{"aa_change": "AA annotation unavailable", "status": "unsupported_programmed_frameshift"}
It will never emit false-positive missense annotations for uncurated frameshift features.

Curated Model Specification (--cds_models resources/annotation_models/cds_models.json)

11. Epidemiological Distance Engine & Phylogenetic Tree

Whole-Genome Pairwise Hamming Distance

Viromics calculates distance matrices in parse_metrics.py using a robust whole-genome consensus pairwise algorithm designed to eliminate sequencing artifacts:

  • Coverage Gate: Only genomic positions with sequencing depth $\ge \text{minConsensusDepth}$ in both samples are evaluated.
  • Major Allele Filter: Only major consensus alleles ($\text{AF} \ge \text{minConsensusFreq}$, default 0.50) are counted to prevent minor subclonal variants from biasing transmission linkages.
  • Deletion Masking: Structural deletions and uncalled bases (N) are omitted from the SNP mismatch numerator and denominator.
  • Missing-Overlap Representation: Reports emit fractional divergence (distance_matrices), raw integer SNP differences (snp_distance_matrices), and pairwise comparable base counts (compared_sites_matrices). Pairs with zero mutually covered bases receive null rather than conflating missing data with 100% divergence.

Midpoint-Rooted Neighbor-Joining & Optional UPGMA Clustering

The client-side dashboard parses report.distance_matrices, snp_distance_matrices, and compared_sites_matrices, defaulting to Midpoint-Rooted Neighbor-Joining (NJ) with an interactive toggle to switch to Rooted UPGMA:

  • Coverage & Overlap Safe-Guards: Samples below the interactive minimum coverage breadth threshold (default 80%) or pairwise comparisons below the minimum comparable sites threshold (or with null pairwise distance) are excluded to prevent dropout artifacts from distorting branch lengths.
  • Neighbor-Joining (Default): Applies Saitou & Nei Q-criterion agglomerative clustering without assuming a strict molecular clock, followed by deterministic midpoint rooting across the longest pairwise tree path so differential viral substitution rates across lineages remain accurately scaled.
  • UPGMA (Optional Toggle): Merges clusters using cluster-size weighted arithmetic means, $$d_{(A \cup B), K} = \frac{|A| \cdot d_{A, K} + |B| \cdot d_{B, K}}{|A| + |B|}$$ with node height $h = d(A, B)/2$ and $2\times$ divergence axis calibration.
  • Machine-Readable Exports: Supports one-click download of rooted Newick trees (.nwk), pairwise distance & SNP CSV matrices, calibrated tree SVGs, and cohort multi-FASTA alignments.

13. Run Report JSON Anatomy

The viromics_run_report.json contract is formally defined in schema/viromics_run_report.schema.json (v2.0.0) and validated by validate_report_schema() in parse_metrics.py. Key fields include:

Field Path Type Description
schema_version / run_id String Schema version ("2.0.0") and deterministic run identifier.
run_config / software_versions Object Complete resolved CLI parameters (including qc_thresholds) and exact tool versions collected from process versions_*.yml files.
min_coverage_threshold Integer The minimum depth threshold applied during this run (e.g. 10 or 50).
references Array List of reference strains with name, length, and sequence.
distance_matrices / snp_distance_matrices / compared_sites_matrices Object Fractional divergence (float | null), raw integer SNP differences, and mutually covered site counts per reference (keyed by distance_matrix_order and distance_matrices_by_name).
samples[].qc_status / qc_reasons / primary_reference String / Array Sample QC tier (PASS/WARN/FAIL) on the highest-coverage contig, reason codes, and primary reference name.
samples[].qc Object Normalized fastp/fastplong read counts, 0.0–1.0 q30_rate_*, mean_read_length_*, and duplication_rate (null when omitted by ONT fastplong).
samples[].coverage[ref] Object Whole-contig & callable-target depth/breadth (callable_mean_depth, callable_breadth_min_cov, qc_basis, qc_status), binned coverage_profile, and reference-coordinate low_coverage_intervals.
samples[].consensus[ref] Object Contains length, gc_content, whole-contig n_content, callable-target internal_n_content/internal_n_count/terminal_n_count, and sequence.
samples[].variants[] Array FILTER-enforced variants computed from FORMAT/AD & FORMAT/DP with is_consensus, gene, aa_change (in-frame vs. frameshift indels), and structured per-gene consequences[].

14. Interactive Web Dashboard Guide

The React web application is fully driven by viromics_run_report.json (v2.0.0 schema with graceful v1 fallback), reading run_config, qc_thresholds, and software_versions dynamically across 5 integrated analytical views:

1. Run Overview

Cohort QC pass rates, dynamic run provenance (platform, variant caller, resolved thresholds, tool versions), deterministic report IDs, reference strain filtering, cohort multi-FASTA download, and a sortable QC table displaying callable & whole-contig breadth/depth alongside server-computed PASS/WARN/FAIL badges and qc_reasons tooltips.

2. Sample Details

Granular sample inspection featuring an interactive Recharts depth profile with internal dropout shading (<ReferenceArea />), an Amplicon Panel QC bar chart and sortable table (when primer/amplicon stats are present), a staggered multi-track SVG Gene Map with exon connectors, sample FASTA export, SVG downloads, and a searchable variant table displaying structured consequences[], Consensus/Subclonal badges, and RFC-4180 CSV export.

3. Mutational Sharing

Epidemiological variant sharing matrix with indel-safe reference-coordinate dropout lookup via low_coverage_intervals. Includes interactive controls for Min Breadth %, Clonal AF % threshold, and All Variants vs. Consensus Only filtering.

4. Phylogenetic Tree

Midpoint-rooted Neighbor-Joining tree (default) with an optional Rooted UPGMA toggle, interactive Min Breadth % and Min Compared Sites guards, a Nearest Genetic Relatives table (% div, SNP counts, and mutually covered sites), and Newick (.nwk), Distance CSV, SVG, and Cohort FASTA exports.

5. Genomics Report Card

Printable clinical epidemiology report card with multi-page PDF pagination. Summarizes deterministic sample/run provenance, QC assessment, and Consensus/Subclonal mutations with clean light-mode print styling.

Crash-Resilient React Architecture

Every dashboard view is wrapped in a dedicated React ErrorBoundary. If malformed data or a rendering glitch occurs in any single view, the application isolates the error with a friendly warning card and a "Retry View" button while keeping the rest of the navigation alive.

15. Troubleshooting & Frequently Asked Questions

Why does my sample show "FAIL" in the Overview status column? ▼
A sample receives a FAIL badge if its callable mean depth is below --qc_warn_depth (default 25x), its callable breadth at --min_coverage is below --qc_warn_breadth (default 80%), or its internal consensus N rate exceeds --qc_warn_max_n (default 10%). Hover over the FAIL badge or inspect qc_reasons in the report JSON to see the exact failing metric.
Why is my sample missing from the Phylogenetic Tree? ▼
To prevent severe phylogenetic distortion, the phylogenetic tree (Neighbor-Joining / UPGMA) excludes samples below the configured minimum coverage breadth threshold (default 80%) across the active reference genome, as well as any pairs with null pairwise distance or fewer mutually covered bases than the Min Compared Sites threshold. Excluded samples and reasons are listed in a notification banner at the top of the tree tab.
Why does a variant show "AA annotation unavailable"? ▼
Viromics operates on a fail-closed principle for biological safety. If a GFF feature indicates a programmed translation exception (such as ribosomal slippage or frameshifts) that does not match an entry in resources/annotation_models/cds_models.json, Viromics refuses to guess the amino acid change. It reports AA annotation unavailable alongside the specific status code (e.g. unsupported_programmed_frameshift).
Can I analyze custom viral pathogens not included in the examples? ▼
Yes! Viromics is virus-agnostic. Simply provide your viral reference genome via --reference your_virus.fasta. If you have primer schemes, supply --primer_bed primers.bed, and if you have annotations, provide --gff annotations.gff3.
How do I adjust memory or CPU allocations for high-throughput runs? ▼
Edit the process block in pipeline/nextflow.config, or pass resource flags on the command line (e.g. --max_cpus 16 --max_memory 32.GB).
